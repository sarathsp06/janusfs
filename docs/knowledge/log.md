Added a hidden `janusfs watchdog --pid <daemon-pid>` command (`cmd/janusfs/watchdog.go`) that the daemon spawns detached at startup and polls the given PID; on death it force-unmounts every mount in the registry that `isMountpoint` still reports as mounted, reusing the existing `unmountKernel` ladder — a clean shutdown has already unmounted everything, so the same sweep is a no-op in that case, with no lease file or handshake needed. `janusfs doctor` now reports watchdog presence and liveness. Measured on this machine: cache-hit ~55 ns, ten-level cache-miss ~90 µs, both meeting NFR-3's budget — recorded in `bench/BASELINE.md`. Both platforms now set `fs.Options.AttrTimeout`/`EntryTimeout`/`NegativeTimeout` to zero explicitly (`mount_darwin.go`, `mount_linux.go`), turning what used to be an accidental omission into a stated, tested decision; `TestReloadTakesEffectWithoutRemount` confirms a policy tightening takes effect on the very next lookup with no remount. Removed the corresponding item from [known gaps](known-gaps.md).

New `internal/nsexec` (capability preflight, `Supported()`). `internal/execrunner` split by build tag: `runner.go`/`rewriter.go` are now `darwin`-only (they exist only to simulate path parity, which Linux no longer needs), and a new `runner_linux.go` (Stage 1) re-execs the janusfs binary with `CLONE_NEWNS|CLONE_NEWUSER` into a new hidden `cmd/janusfs/nsmount_linux.go` `__nsmount` command (Stage 2), which makes the mount tree recursively private, then — **deviating from the PRP's literal pseudocode** — bind-mounts `src` to a private shadow path and backs the FUSE adapter by the shadow path while mounting at the real `src`, so backing reads can never re-enter the mount they're serving regardless of what sits at `src`. Wrote (but could not run) `internal/execrunner/isolation_linux_test.go` and `isolation_linux_bench_test.go`, gated `linux && fuseintegration`. **Must be run on a real Linux machine before this PRP is treated as validated** — see [platform-isolation.md](platform-isolation.md)'s "As implemented" section and [PRPs/README.md](/PRPs/README.md).

## 2026-07-27

* **Update**: Implemented [PRP 05](/PRPs/05-dirfd-backing-layer.md) for the read path. New `internal/backing` package retains a directory descriptor for the source root and exposes `OpenAt`/`StatAt`/`LstatAt`/`ReadlinkAt`/`UnlinkAt`/`RenameAt`/`MkdirAt`/`SymlinkAt`/`LinkAt`/`ChmodAt` — each guarded by a component-wise `validRel` check that rejects `..`, absolute paths, and empty components while accepting legitimate names like `..foo`. `internal/mount` now acquires a `Backing *backing.Root` in `newJanusRoot` before `fs.Mount`, and routes the security-relevant read path through it: `contentKey` uses `Backing.StatAt`, `decisionFor` uses `Backing.LstatAt`, `readRaw` opens via `Backing.OpenAt` with `O_NOFOLLOW`, and the provider's rebuild/oversize path receives a `provider.Opener` that opens through the same descriptor rather than re-resolving the path string — closing the window between the decision and the bytes actually read. `ContentKey.Path` stays a string because it is only a cache-map identity, never an access path (see the comment at `janus_node.go:691`). Mutation operations still route through `LoopbackNode` for now — deliberately split, per the PRP's incremental guidance, since the read path is the security-critical one and replacing the mutation/dir-stream plumbing is a much larger separate change. A `testRaceHook` seam sits between the decision and the backing I/O in `maskedHandle.Read` so a future `fuseintegration` test can race a symlink swap deterministically. Removed the corresponding item from [known gaps](known-gaps.md).
* **Update**: Implemented [PRP 06](/PRPs/06-process-identity.md) Tasks 1 and 2. New `internal/procid` package: `Identity`, `MemRegistry` (session-token indexed, thread-safe, per-PID cache), and `IsAgent` with the four-step resolution order (cached verdict revalidated by start time → `JANUSFS_SESSION` environ scrape → ancestry walk against registered roots → not-an-agent). Platform seams via `KERN_PROC_PID`/`KERN_PROCARGS2` on darwin and `/proc/<pid>/stat`/`/proc/<pid>/environ` on linux, with the stat parser anchored on the last `)` so an executable name containing spaces or parens does not misalign later fields. Task 1's gate passed: `BenchmarkStartTime` ~9.2 µs, `BenchmarkIsAgentCacheHit` ~9.1 µs, `BenchmarkAncestryWalk` (depth 5) ~46 µs on darwin/arm64 — comfortably under the 250 µs per-op budget (recorded in `bench/BASELINE.md`). **Load-bearing caveat discovered while implementing Task 2 on macOS 26.5.2**: `KERN_PROCARGS2` no longer returns the `envp` region for a cross-process same-uid read; only `argc` + `exec_path` + `argv` come back. PRP 06's "If this is wrong" section named exactly this outcome as report-rather-than-ship-quietly. Consequence: on recent darwin, the environ path (step 2) is unavailable and the ancestry walk (step 3) becomes primary; a re-parented agent subprocess (e.g. after `setsid`) silently loses its filtered view. Recorded in `docs/knowledge/process-identity.md`. Tasks 3 (execrunner session registration with a barrier) and 4 (plumb caller through `resolve()`/`decisionFor()`, gated on path-preserving mode) are **deferred until PRP 07 exists**: with no path-preserving mode yet to gate the identity check on, plumbing identity through the adapter would either short-circuit unused or add per-op cost for no beneficiary.
* **Update**: Implemented [PRP 08](/PRPs/08-reload-revocation.md). Added `internal/mount/revocable.go`: a `revocableHandle` wrapper that embeds the concrete `*fs.LoopbackFile` returned by `LoopbackNode.Open` (embedding the empty `fs.FileHandle` interface would promote nothing and leak the fd) and re-checks `resolve()` on every Read and Write, failing closed with `EACCES` if a reload has tightened the decision to Masked or Hidden. Every other file operation — Release, Flush, Fsync, Getlk/Setlk/Setlkw, Lseek, Setattr, Getattr, PassthroughFd — forwards through Go method promotion unchanged. The per-read cost is one cache-hit `engine.Resolve` (~55 ns since PRP 03 memoized it), so this hardening is essentially free on the hot path. `fuseintegration` regression test opens a file while Allowed, reloads the engine with a `.janusignore` covering that file, and asserts the next read on the SAME fd returns `EACCES`. Removed the corresponding item from [known gaps](known-gaps.md).

## 2026-08-03

* **Implemented [PRP 09](/PRPs/09-macos-seatbelt-exec.md)**: `janusfs exec --sandbox` on macOS. New `internal/execrunner/sandbox_darwin.go` (`darwin`-only): `sandboxAvailable` (fail-closed check for `/usr/bin/sandbox-exec`), `canonicalizeWithFirmlinkTwin` (resolves symlinks and, for paths under `/Users`, `/Applications`, `/Library`, `/private/var`, also returns the `/System/Volumes/Data` firmlink twin — Seatbelt matches the resolved path, and naming only one form is a silent fail-open bypass), `canonicalDenyTargets`/`canonicalReadOnlyDenyTargets`, and `sandboxProfile` (renders a `(version 1)(allow default)(deny file-read*/file-write* <source>)(deny file-read* <~/.janusfs>)(allow file-read*/file-write* <mountpoint>)` profile — the mountpoint re-allow is positioned last so it wins regardless of which deny rule happens to be its ancestor). `runner.go`'s `Run` gained a `sandbox bool` parameter; when set, it wraps the already-built child command in `sandbox-exec -p <profile> --`, additive to the existing CWD-hijack/argv-rewrite/env-scrub flow. `runner_linux.go` accepts-and-ignores the same parameter (the mount namespace already enforces read+write; a second mechanism would be redundant). `cmd/janusfs/exec.go` hand-parses `--sandbox` out of the pre-`--` args (the command uses `DisableFlagParsing: true`, so cobra's own flag parsing never runs) and extended the help text; also removed a pre-existing `FR-Exec-1/FR-Exec-2` citation from a code comment while touching the file, per the project's own convention against citing SPEC/FR numbers in comments.
* **Real bug found and fixed via end-to-end testing against a live daemon and mount** (not caught by the original spike or the first unit-test pass, both of which used disjoint temp dirs): the default mount root is `~/.janusfs/mounts/...`, so the `~/.janusfs` read-only deny — added as defense-in-depth so a confined child can't read JanusFS's own config/state — also denied the mountpoint itself whenever the user hadn't customized `--root`, breaking the one thing `--sandbox` promises to leave alone (`cat` through the mountpoint returned `Operation not permitted` instead of the masked bytes). Fixed by adding an explicit `mustAllow` parameter to `sandboxProfile`, asserted last in the profile so it wins over any earlier deny regardless of ancestry. Added a regression test reproducing the exact layout (`TestSandboxExecMountpointNestedUnderReadOnlyDenyStillWorks`, `internal/execrunner/sandbox_darwin_integration_test.go`) plus a `TestSandboxProfile` subtest for the same collision at the unit level.
* Also verified by hand against a live daemon+mount, beyond the spike's original scope: a real-path secret reaching the child through an **environment variable** (a channel `janusfs exec`'s argv-rewriting cannot touch, standing in for a symlink or dynamically-computed path) is denied by the sandbox even though it would bypass the advisory argv rewrite entirely — this is the actual security property `--sandbox` provides beyond Option A's best-effort compatibility shim.
* `make verify` (fmt-check, vet, test-race) green across every package; `make leak-oracle` unaffected (this PRP touches `execrunner/`, not `mount/`/`redact/`/`provider/`); cross-compiles clean for `linux/amd64` and `linux/arm64` with `--sandbox` accepted-and-ignored there. Recorded a new known gap (item 3 in [known-gaps.md](known-gaps.md)): `--sandbox` leaves loopback networking allowed by design (denying it would break agents needing localhost), so a confined child can still reach the daemon's `GET /api/v1/reveal` — not currently exploitable (the bearer token is in-memory only and unreachable by the child) but a structural reachability gap worth closing with a scoped daemon-port deny later. Updated [platform-isolation.md](platform-isolation.md) (new "Option D"), [exec-and-path-parity.md](exec-and-path-parity.md), and [`docs/SEATBELT_SPIKE.md`](/docs/SEATBELT_SPIKE.md) (status flipped to implemented) to match the as-built design.
